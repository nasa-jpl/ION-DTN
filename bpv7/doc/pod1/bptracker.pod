=head1 NAME

bptracker - ION Bundle Protocol transmission tracker and management utility with enhanced debugging

=head1 SYNOPSIS

B<bptracker> [B<-v>] [B<-vv>] [B<-vvv>] [B<-h>] I<source_eid> [I<dest_eid>]

=head1 DESCRIPTION

B<bptracker> is an interactive Bundle Protocol utility that provides real-time
bundle tracking and management with Bundle Protocol status report support.  It
operates in a fully interactive mode where users can configure transmission
parameters, send individual bundles, and monitor bundle status through the
Bundle Protocol status report mechanism.

The utility opens a source endpoint with detention enabled, allowing detailed
tracking of sent bundles.  Users can configure status report request flags and
specify a report-to endpoint to receive Bundle Protocol status reports for
transmitted bundles.

B<Note>: To receive and display status reports, use B<bptrace> in listen-only
mode (B<bptrace -listen> I<reportEid>) on the same or different terminal.  Status
report reception directly in bptracker is planned for a future release.

=head1 OPTIONS

=over 4

=item B<-v>

Enable verbose output (debug level 1). Shows basic operations and status changes.

=item B<-vv>

Enable more verbose output (debug level 2). Shows detailed function calls and tracking steps.

=item B<-vvv>

Enable most verbose output (debug level 3). Shows verbose internal state and queue details.

=item B<-h>, B<--help>

Display usage information and exit.

=back

=head1 PARAMETERS

=over 4

=item I<source_eid>

Source endpoint identifier (e.g., ipn:1.1).  Must be a valid EID that the local
node can open as a source endpoint. Required.

=item I<dest_eid>

Optional default destination endpoint identifier (e.g., ipn:2.1).  If provided,
this sets the default destination that can be used for convenience.  Individual
B<send> commands can override this by specifying a different destination.

=back

=head1 INTERACTIVE COMMANDS

B<bptracker> provides a fully interactive command interface immediately upon startup:

=over 4

=item B<config> [I<param>] [I<value>]

Configure transmission parameters or show current configuration.  When called without
arguments, displays all current settings.  Configuration parameters:

=over 8

=item B<dest> I<eid>

Set default destination endpoint.  The B<send> command can override this on a per-bundle
basis.  Example: config dest ipn:2.1

=item B<report> I<eid>

Set the report-to endpoint where Bundle Protocol status reports will be sent.
Example: config report ipn:1.2

=item B<srr> I<flags>

Set status report request flags.  Can be specified as hex (e.g., 0f) or comma-separated
text flags: rcv (received), fwd (forwarded), dlv (delivered), del (deleted).
Example: config srr rcv,dlv  or  config srr 0f

=item B<ttl> I<seconds>

Set default time-to-live in seconds.  Example: config ttl 300

=item B<priority> I<0-2>

Set default priority: 0=bulk, 1=standard, 2=expedited.  Example: config priority 1

=back

=item B<send> [I<dest_eid>] I<payload_size>

Send a bundle with the given payload size (1-65536 bytes).  The destination can be
specified explicitly or omitted to use the default destination set via B<config dest>.
If provided, the destination parameter overrides the configured default.  Uses current
configuration for status report flags, report-to endpoint, TTL, and priority.

Examples:
  send ipn:2.1 1024    (explicit destination)
  send 1024            (uses configured default destination)

=item B<reports> [I<bundle_id>]

Show status report statistics (not yet implemented - use B<bptrace -listen> to view reports).

=item B<q>, B<quit>

Release all detained bundles and exit the program gracefully.

=item B<s>, B<status>

Display current tracker status including active bundles, completion statistics,
success rates, and current debug level.

=item B<l>, B<list>

List all tracked bundles with enhanced information including:

=over 8

=item * Bundle ID and current status

=item * Age in seconds since bundle was sent

=item * Source EID extracted from bundle

=item * Creation time in YYYY-MM-DD HH:MM:SS.mmm.count format

=item * Current queue status within ION

=item * Bundle object address for transmitted bundles

=back

=item B<r> I<id>, B<release> I<id>

Release a specific bundle by ID from detention, allowing it to be deleted when
all retention constraints are removed.

=item B<ra>, B<release-all>

Release all currently detained bundles from detention.

=item B<suspend> I<id>, B<sp> I<id>

Suspend transmission of a specific bundle by ID.  Only works for bundles still
in local storage that haven't been transmitted yet.

=item B<resume> I<id>, B<res> I<id>

Resume transmission of a previously suspended bundle by ID.

=item B<h>, B<help>

Display comprehensive help information about available commands, bundle information
fields, status meanings, and current debug level.

=back

=head1 BUNDLE STATES

B<bptracker> tracks bundles through the following states:

=over 4

=item B<PENDING>

Bundle is awaiting transmission or currently being processed for transmission.

=item B<SUSPENDED>

Bundle transmission has been manually suspended using ION's bp_suspend() function
and is held in suspension until resumed.

=item B<TRANSMITTED>

Bundle has been successfully transmitted by the convergence layer and is now
detained in local storage for manual management.

=item B<COMPLETED>

Bundle has been manually released from detention and is eligible for deletion
when all retention constraints are satisfied.

=back

=head1 QUEUE STATUS INFORMATION

B<bptracker> provides detailed visibility into ION's internal queue status for each bundle:

=over 4

=item B<PLAN>

Bundle is in the egress plan queue awaiting route processing.

=item B<DUCT>

Bundle is in the outduct transmission queue awaiting convergence layer processing.

=item B<FWD>

Bundle is in the forwarding queue awaiting forwarding decisions.

=item B<DLV>

Bundle is in the delivery queue awaiting local delivery.

=item B<DETAINED>

Bundle is held in detention post-transmission.

=item B<CLEAR>

Bundle is not currently in any ION queues (transmission complete).

=item B<RELEASED>

Bundle has been manually released from detention.

=back

Multiple queue statuses may be displayed simultaneously if a bundle is present
in multiple queues.

=head1 DEBUG LEVELS

B<bptracker> supports four debug verbosity levels:

=over 4

=item B<Level 0> (default)

No debug output.  Only normal operation messages and user interactions are displayed.

=item B<Level 1> (B<-v>)

Basic operations and status changes including bundle send/suspend/resume/release
operations and monitoring loop activities.

=item B<Level 2> (B<-vv>)

Detailed function calls and tracking steps including SDR transactions, bundle
object operations, and tracking record updates.

=item B<Level 3> (B<-vvv>)

Verbose internal state and queue details including bundle object reads, queue
status changes, and detailed ION interaction debugging.

=back

Debug output is sent to stderr while normal program output goes to stdout,
allowing for clean output redirection.

=head1 ENHANCED BUNDLE INFORMATION

Each tracked bundle displays comprehensive information:

=over 4

=item B<Bundle ID>

Sequential identifier assigned by bptracker (1, 2, 3, ...).

=item B<Status>

Current bundle state (PENDING, SUSPENDED, TRANSMITTED, COMPLETED).

=item B<Age>

Seconds elapsed since the bundle was initially sent.

=item B<Source EID>

Original source endpoint identifier extracted from the bundle header.

=item B<Creation Time>

Bundle creation timestamp in ION DTN time format converted to human-readable
YYYY-MM-DD HH:MM:SS.mmm.count format showing both millisecond precision and
sequence count.

=item B<Queue Status>

Current location within ION's internal queue system, providing visibility into
bundle processing state.

=back

=head1 PAYLOAD FORMAT

Each bundle contains a test payload filled with a repeating byte pattern where
each byte contains the value (byte_position % 256).  This creates a predictable
test pattern useful for verifying payload integrity.

=head1 BUNDLE DETENTION

B<bptracker> uses BP detention to retain bundles in local storage even after
transmission.  This allows for:

=over 4

=item *

Real-time status monitoring of transmitted bundles with queue visibility

=item *

Manual control over bundle lifecycle management

=item *

Detailed inspection of bundle transmission behavior through ION queues

=item *

Testing of bundle suspension and resumption capabilities

=item *

Enhanced debugging of bundle processing flow

=back

Detained bundles must be explicitly released to be eligible for deletion from
the bundle database.

=head1 SIGNAL HANDLING

B<bptracker> handles SIGINT (Ctrl+C) and SIGTERM signals gracefully by:

=over 4

=item *

Releasing all detained bundles

=item *

Cleaning up tracking data structures and SDR resources

=item *

Terminating the input handler thread safely

=item *

Closing the Bundle Protocol SAP

=item *

Detaching from ION

=back

=head1 THREADING

The utility uses multiple threads with proper synchronization:

=over 4

=item *

B<Main thread>: Bundle status monitoring, queue status updates, and application control

=item *

B<Input thread>: Interactive command processing with 2-second startup delay

=back

Thread synchronization ensures safe access to shared tracking data and SDR operations.

=head1 EXAMPLES

=over 4

=item Send 5 bundles of 1024 bytes each (silent operation):

    % bptracker ipn:1.1 ipn:2.1 1024 5

=item Send with basic debug output:

    % bptracker -v ipn:1.1 ipn:2.1 1024 5

=item Send with detailed debug output:

    % bptracker -vv ipn:1.1 ipn:2.1 1024 5

=item Send with maximum verbosity:

    % bptracker -vvv ipn:1.1 ipn:2.1 1024 5

=item Show help and exit:

    % bptracker -h

=item Interactive session example:

    % bptracker -v ipn:1.1 ipn:2.1 1024 3
    > list              # Show all bundles with enhanced info
    ID  Status       Age(s)  Source_EID    Creation_Time         Queue_Status
    --- ------------ ------- ------------- -------------------- ---------------
    1   TRANSMITTED  45      ipn:1.1       2024-01-15 14:30:25.123.1  CLEAR
    2   PENDING      12      ipn:1.1       2024-01-15 14:30:25.223.2  PLAN DUCT
    3   SUSPENDED    8       ipn:1.1       2024-01-15 14:30:25.323.3

    > suspend 2         # Suspend bundle 2 (if still local)
    > status            # Check current statistics
    > resume 2          # Resume bundle 2
    > release 1         # Release bundle 1 from detention
    > quit              # Release all and exit

=back

=head1 EXIT STATUS

=over 4

=item B<0>

Successful completion.

=item B<1>

Invalid command line arguments, initialization failure, or system error.

=back

=head1 FILES

None.

=head1 ENVIRONMENT

No special environment dependencies.  Uses standard ION environment configuration.

=head1 DIAGNOSTICS

B<bptracker> reports various diagnostic messages based on debug level:

=over 4

=item B<Normal operation>

Bundle transmission confirmations, status changes, and interactive command responses.

=item B<Debug level 1>

Basic operation logging including send/suspend/resume/release operations and
monitoring activities.

=item B<Debug level 2>

Detailed function tracing including SDR transactions, bundle tracking setup,
and status update procedures.

=item B<Debug level 3>

Verbose internal state including bundle object details, queue status changes,
and ION interaction debugging.

=item B<Error conditions>

ION system errors, memory allocation failures, SDR transaction failures, and
invalid operations are reported through ION's standard error reporting mechanism.

=item B<Status summaries>

Periodic and on-demand statistics about bundle transmission success rates,
current active bundle counts, and debug level information.

=back

=head1 BUGS

=over 4

=item *

Bundle suspension and resumption only work for bundles still in local storage.
Once bundles have been forwarded to the next hop, they cannot be suspended or resumed.

=item *

Queue status information depends on ION's internal bundle object structure and
may not reflect all possible queue states in complex routing scenarios.

=item *

Debug output at level 3 can be quite verbose and may impact performance during
high-throughput testing scenarios.

=item *

Critical bundles (those with BP_MINIMUM_LATENCY flag) cannot be suspended by
ION's design.

=back

Report bugs to ION development team.
