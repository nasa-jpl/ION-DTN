=head1 NAME

ipnrc - IPN scheme configuration commands file

=head1 DESCRIPTION

IPN scheme configuration commands are passed to B<ipnadmin> either in a file of
text lines or interactively at B<ipnadmin>'s command prompt (:).  Commands
are interpreted line-by-line, with exactly one command per line.

IPN scheme configuration commands (a) establish egress plans for direct
transmission to neighboring nodes that are members of endpoints identified
in the "ipn" URI scheme, (b) establish static default routing rules
for forwarding bundles to specified destination nodes, and (c) establish
override rules - applicable to bundles characterized by specific sources,
destinations, and/or data labels - for routing and/or quality of service.

The egress B<plan> established for a given node associates a B<duct expression>
with that node.  Each duct expression is a string of the form
"I<protocol_name>/I<outduct_name>" signifying that the bundle is to be
queued for transmission via the indicated convergence layer protocol outduct.

Note that egress plans B<must> be established for all neighboring nodes,
regardless of whether or not contact graph routing is used for computing
dynamic routes to distant nodes.  This is by definition: if there isn't
an egress plan to a node, it isn't considered a neighbor.

Also note that egress plans can now be established by bpadmin and such
egress plans may enable selection among multiple outducts; see the bprc(5)
man page for details.

Static default routes are declared as B<exits> in the ipn-scheme routing
database.  An exit is a range of node identifiers identifying a set of nodes
for which defined default routing behavior is established.  Whenever a
bundle is to be forwarded to a node whose fully-qualified node number is
in the exit's node identifier range B<and> it has not been possible to
compute a dynamic route to that node from the contact schedules that
have been provided to the local node B<and> that node is not a neighbor
to which the bundle can be directly transmitted, BP will forward the
bundle to the B<gateway> node associated with this exit.  The gateway
node for any exit is identified by an endpoint ID, which might or might
not be an ipn-scheme EID; regardless, directing a bundle to the gateway
for an exit causes the bundle to be re-forwarded to that intermediate
waypoint endpoint.  Multiple exits may encompass the same fully-qualified
node number, in which case the gateway associated with the most
restrictive exit (the one with the smallest range) is always selected.

An exit is therefore the last routing mechanism consulted.
Forwarding in the ipn scheme considers, in order:
a routing override, if one matches (see below);
a dynamic route computed by CGR from the contact plan,
attempted only if the destination node resides in a region
that the local node also resides in;
direct transmission to the destination node, if it is a neighbor;
and finally the narrowest applicable exit.
Note that a destination in an unknown region skips CGR entirely,
so for such destinations an exit is the only route
other than direct transmission.

Because a bundle directed to a gateway is simply re-forwarded to that
endpoint, the gateway must itself be reachable from the local node:
an exit is useful only if there is an egress plan
to the gateway node, or a route to it can be computed.
An exit whose gateway cannot be reached does not make the
destination reachable.

B<Note> that "exits" were termed "groups" in earlier versions of ION.  The
term "exit" has been adopted instead, to minimize any possible confusion
with multicast groups.  To protect backward compatibility, the keyword
"group" continues to be accepted by ipnadmin as an alias for the new keyword
"exit", but that older terminology is deprecated.

Routing and quality-of-service overrides may also be managed:

=over 4

A routing override declares a neighboring node to which all bundles must
be forwarded that meet specified criteria.  This override is strictly local,
affecting only forwarding from the local node, and it is applied before
any route computed by CGR or IRR is considered.  A routing override may
additionally designate a specific outduct (identified by duct expression
as defined in the bprc(5) man page) that must be used for transmission to
this neighboring node.

A quality-of-service override declares the quality of service (priority and
ordinal and [optionally] quality-of-service flags) that will condition
- in terms of order and outduct selection - the forwarding of all bundles
that meet specified criteria.  Again this override is strictly local,
affecting only forwarding from the local node.

=back

The formats and effects of the IPN scheme configuration commands are
described below.

=head1 GENERAL COMMANDS

=over 4

=item B<?>

The B<help> command.  This will display a listing of the commands and their
formats.  It is the same as the B<h> command.

=item B<#>

Comment line.  Lines beginning with B<#> are not interpreted.

=item B<e> { 1 | 0 }

Echo control.  Setting echo to 1 causes all output printed by ipnadmin to be
logged as well as sent to stdout.  Setting echo to 0 disables this behavior.

=item B<v>

Version number.  Prints out the version of ION currently installed.  HINT:
combine with B<e 1> command to log the version number at startup.

=item B<h>

The B<help> command.  This will display a listing of the commands and their
formats.  It is the same as the B<?> command.

=item B<q>

The B<quit> command.  Terminates the program immediately.

=back

=head1 PLAN COMMANDS

=over 4

=item B<a plan> I<node_identifier> I<duct_expression> [I<nominal_data_rate>]

The B<add plan> command.  This command establishes an egress plan for
the bundles that must be transmitted to the neighboring node identified
by I<node_identifier>.  (NOTE that a I<node_identifier> may be either an
expression of the form "I<allocator_nbr>.I<node_number>" or simply a "fully
qualified node number" of up to 20 digits.)  The I<nominal_data_rate> is
the assumed rate of transmission to this node in the absence of contact
plan information.  A I<nominal_data_rate> of zero (the default) in the
absence of contact plan information completely disables rate control.

I<duct_expression> identifies the convergence-layer outduct over which
bundles for this plan are queued.  It is a string of the form
"I<protocol_name>/I<duct_name>", where I<protocol_name> is the
convergence-layer protocol (e.g., B<ltp>, B<tcp>, B<stcp>, B<udp>,
B<bssp>, B<dgr>, B<bibe>) and I<duct_name> is the name of an outduct that
has already been declared for that protocol via B<a outduct> in
bprc(5).  The form of I<duct_name> is protocol-specific: for B<ltp> and
B<bssp> it is the remote engine number (e.g., B<18>); for B<tcp>,
B<stcp>, B<udp>, and B<dgr> it is the remote endpoint as
"I<host>:I<port>" (e.g., B<127.0.0.1:4556>); for B<bibe> it is an
ipn-scheme EID (e.g., B<ipn:2.0>).  For instance,
"B<ltp/18>" directs bundles to the LTP outduct addressing engine 18,
and "B<stcp/127.0.0.1:4556>" directs bundles to the STCP outduct that
connects to 127.0.0.1 on port 4556.  The named outduct must already
exist; B<a plan> does not create the outduct itself.

B<Note that the plan commands consumed by ipnadmin are a simplified
shortcut for submitting plan commands as consumed by bpadmin (see bprc(5)).
The syntax of these commands is DIFFERENT from that of the more general
and more powerful bpadmin commands.>

=item B<c plan> I<node_identifier> I<nominal_data_rate>

The B<change plan> command.  This command changes the nominal data rate
for the indicated plan.

=item B<d plan> I<node_identifier>

The B<delete plan> command.  This command deletes the egress plan
for the node identified by I<node_identifier>.

=item B<i plan> I<node_identifier>

This command will print information about the egress plan for the node
identified by I<node_identifier>.

=item B<l plan>

This command lists all egress plans established in the IPN database for the
local node.

=back

=head1 EXIT COMMANDS

=over 4

=item B<a exit> I<first_node_identifier> I<last_node_identifier> I<gateway_node_ID>

The B<add exit> command.  This command establishes an "exit" for static
default routing as described above.  The gateway node ID is a BP endpoint
ID; for the ipn scheme, this would simply be any ipn-scheme endpoint ID
with service number equal to zero.

=item B<c exit> I<first_node_identifier> I<last_node_identifier> I<gateway_node_ID>

The B<change exit> command.  This command changes the gateway node ID for the
exit identified by I<first_node_identifier> and I<last_node_identifier> .

=item B<d exit> I<first_node_identifier> I<last_node_identifier>

The B<delete exit> command.  This command deletes the exit identified
by I<first_node_identifier> and I<last_node_identifier>.

=item B<i exit> I<first_node_identifier> I<last_node_identifier>

This command will print information (the gateway node ID) about the
exit identified by I<first_node_identifier> and I<last_node_identifier>.

=item B<l exit>

This command lists all exits defined in the IPN database for the local node.

=back

=head1 OVERRIDE COMMANDS

=over 4

=item B<a rtovrd> I<data_label> I<dest_node_identifier> I<source_node_identifier> I<neighbor> [I<duct_expression>]

The B<add rtovrd> command.  This command cause bundles characterized by
I<data_label> ("all other data labels" if this label number is zero),
I<dest_node_identifier> ("all other destinations" if this node
identifier is zero) and I<source_node_identifier> ("all other sources"
if this node identifier is zero) to be forwarded to I<neighbor>.  If
I<duct_expression> is noted, all such bundles will be forwarded using
the indicated outduct.

=item B<c rtovrd> I<data_label> I<dest_node_identifier> I<source_node_identifier> I<neighbor> [I<ductExpression>]

The B<change rtovrd> command.  This command changes the override neighbor
for the override identified by I<data_label>, I<dest_node_identifier>, and
I<source_node_identifier>.  To cause ION to forget the override, use -1 as
I<neighbor>.  If I<duct_expression> is noted, the indicated outduct will
become the outduct that is used for forwarding to the indicated neighboring
node; if I<duct_expression> is '' then the duct expression associated with
this override is removed.

=item B<a cosovrd> I<data_label> I<dest_node_identifier> I<source_node_identifier> I<priority> I<ordinal> [I<qos_flags>]

The B<add cosovrd> command.  This command cause bundles characterized by
I<data_label> ("all other data labels" if this label number is zero),
I<dest_node_identifier> ("all other destinations" if this node
identifier is zero) and I<source_node_identifier> ("all other sources"
if this node identifier is zero) to have their effective quality of service
(priority and ordinal and, optionally, additional quality-of-service flags)
changed as noted.

=item B<c cosovrd> I<data_label> I<dest_node_identifier> I<source_node_identifier> I<priority> I<ordinal> [I<qos_flags>]

The B<change cosovrd> command.  This command changes the effective quality of
service (priority and ordinal and, optionally, additional quality-of-service
flags) for the override identified by I<data_label>, I<dest_node_identifier>,
and I<source_node_identifier>.  To cause ION to forget the override, use -1
as I<priority>.

=item B<d ovrd> I<data_label> I<dest_node_identifier> I<source_node_identifier>

The B<delete override> command.  This command deletes any overrides identified
by I<data_label>, I<dest_node_identifier>, and I<source_node_identifier>.

=item B<i ovrd> I<data_label> I<dest_node_identifier> I<source_node_identifier>

This command will print information for all overrides identified
by I<data_label>, I<dest_node_identifier>, and I<source_node_identifier>.

=item B<l ovrd>

This command lists all overrides defined in the IPN database for the local node.

=back

=head1 EXAMPLES

=over 4

=item a plan 18 ltp/18

Declares the egress plan to use for transmission from the local node to
neighboring node 18.  The duct expression "B<ltp/18>" names the LTP
outduct whose I<duct_name> is the remote engine number 18 (declared
separately via B<a outduct ltp 18 ltpclo> in bprc(5)).  By default,
any bundle for which the computed "next hop" node is node 18 will be
queued for transmission on this outduct.

=item a plan 19 stcp/127.0.0.1:4556

Declares the egress plan for neighboring node 19, using the STCP
outduct that connects to host 127.0.0.1 on port 4556.  The duct
expression here illustrates the "I<host>:I<port>" form of I<duct_name>
that B<tcp>, B<stcp>, B<udp>, and B<dgr> use.

=item a exit 1 999 dtn://stargate

Declares a default route for bundles destined for all nodes whose fully
qualified node numbers are in the range 1 through 999 inclusive: absent
any other routing decision, such bundles are to be forwarded to
"dtn://stargate".

=item a plan 2 udp/127.0.0.1:6002

=item a exit 3 3 ipn:2.0

Declares an all-ipn default route through a single gateway.  Bundles
destined for node 3, which is not a neighbor and for which no route can be
computed, are forwarded to node 2 for re-forwarding.  The egress plan is
what makes the gateway reachable; the exit alone would not deliver the
bundle.  Note the service number of zero in the gateway's endpoint ID.

=item a rtovrd 0 3 0 2

Forces every bundle destined for node 3 to be forwarded to neighboring
node 2, whatever route would otherwise have been chosen -- in contrast to
the exit above, which applies only when nothing else works.  The zeroes
match any data label and any source.

=back
