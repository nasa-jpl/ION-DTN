=head1 NAME

xlso - generic transport-agnostic LTP link service output task

=head1 SYNOPSIS

B<xlso> I<transport_endpoint_spec> I<remote_engine_nbr>

=head1 DESCRIPTION

B<xlso> is a background "daemon" task that extracts LTP segments from the
queue of segments bound for the indicated remote LTP engine and hands each
one to a swappable transport backend.  The transport seam (declared in
B<xlsa.h>, with five C<xport_*> functions) lets a single output-daemon
skeleton drive any byte-oriented or datagram lower layer -- a UART, a
SpaceWire link, an FPGA FIFO, a shared-memory ring, or any other medium --
without changes to the engine coupling itself.

I<transport_endpoint_spec> is parsed by the backend.  The reference
shared-memory backend (B<xport_shm>) accepts C<shm:I<name>> and uses
C</xlsa.I<name>> as the underlying POSIX shared-memory object name; the
length-framed byte-stream backend (B<xport_serial>) accepts
C<serial:I</dev/path>>.  Backend selection is a build-time option
(B<--with-xlsa-backend>); see the in-tree B<DESIGN.md> for details.

I<remote_engine_nbr> is the LTP engine number of the peer.

Each "span" of LTP data interchange between the local LTP engine and a
neighboring LTP engine requires its own link service output task, such
as B<xlso>.  All link service output tasks are spawned automatically by
B<ltpadmin> in response to the 's' command that starts operation of the
LTP protocol, and they are all terminated by B<ltpadmin> in response to
an 'x' (STOP) command.

=head1 EXIT STATUS

=over 4

=item "0"

B<xlso> terminated normally, for reasons noted in the B<ion.log> file.  If
this termination was not commanded, investigate and solve the problem
identified in the log file and use B<ltpadmin> to restart B<xlso>.

=item "1"

B<xlso> terminated abnormally, for reasons noted in the B<ion.log> file.
Investigate and solve the problem identified in the log file, then use
B<ltpadmin> to restart B<xlso>.

=back

=head1 FILES

No configuration files are needed.  The selected transport backend may
consume environment variables for impairment/tuning knobs; see the
ENVIRONMENT section below for the reference shared-memory backend.

=head1 ENVIRONMENT

When built with the reference shared-memory backend, B<xlso> honors the
following environment variables (all optional):

=over 4

=item XLSA_DELAY_US

One-way propagation delay per segment, microseconds.

=item XLSA_JITTER_US

Uniform +/- jitter added to XLSA_DELAY_US, microseconds.

=item XLSA_DROP_PPM

Drop probability, parts per million.

=item XLSA_RATE_BPS

Emulated radio rate, bytes/sec.  Zero means unlimited.

=item XLSA_SLOTS

Rate-buffer depth in segments.  Default 1024.  All processes attached to
the same ring must use the same value.

=back

These knobs model the emulator's radio, not the LTP engine.  ION's own
contact-plan I<localXmitRate> remains a separate number set via
B<ionadmin>; see B<DESIGN.md> for the rationale.

=head1 DIAGNOSTICS

The following diagnostics may be issued to the B<ion.log> log file:

=over 4

=item xlso can't initialize LTP.

B<ltpadmin> has not yet initialized LTP protocol operations.

=item No such engine in database.

I<remote_engine_nbr> is invalid, or the applicable span has not yet
been added to the LTP database by B<ltpadmin>.

=item LSO task is already started for this span.

Redundant initiation of B<xlso>.

=item xlso can't open transport.

The selected backend failed to bring up the lower layer.  Check the
endpoint spec and the backend-specific errtext in the log.

=item Segment too big for xlso transport.

A span's I<maxSegmentSize> exceeds B<XLSA_BUFSZ>.  Lower the
I<maxSegmentSize> in B<ltpadmin>, or rebuild after raising B<XLSA_BUFSZ>
in B<xlsa.h>.

=item xlso failed sending segment.

The backend returned a fatal error.  Inspect errtext and restart B<xlso>.

=back
