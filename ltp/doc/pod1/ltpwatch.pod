=head1 NAME

ltpwatch - Licklider Transmission Protocol (LTP) session status monitor

=head1 SYNOPSIS

B<ltpwatch> [B<-a>] [B<-c>] [B<-t> I<type>] [B<-s> I<session>] [B<-e> I<engineId>] [I<interval> [I<count>]]

=head1 DESCRIPTION

B<ltpwatch> displays the current status of LTP sessions for all configured
spans (or a specific span if filtered).  It shows both active sessions and
recently completed sessions that are still in the "dead" lists awaiting
cleanup.

For each session, B<ltpwatch> displays the session number, current status,
client service ID, data lengths, and retransmission count.  Sessions are
organized by span and separated into export (outbound) and import (inbound)
categories.

B<ltpwatch> can run in one-shot mode (default) or periodically refresh the
display at a specified interval.

=head1 OPTIONS

=over 4

=item B<-a>

Show only active sessions.  When this flag is set, dead (completed and
canceled) sessions are omitted from the output entirely and the header
line shows only the active count (the "Dead: N" portion is suppressed).
This is useful during bench testing or debugging to focus on sessions
that are currently in-flight.

=item B<-c>

Summary count mode.  Instead of printing individual session rows,
B<ltpwatch> prints a per-status count table for each section (export
and/or import).  Only statuses with at least one session are shown.
This flag composes with B<-a>, B<-t>, B<-e>, and B<-s>.

=item B<-t> I<type>

Filter sessions by type. Valid values are:

=over 4

=item B<export>

Show only export (outbound/sending) sessions.

=item B<import>

Show only import (inbound/receiving) sessions.

=back

If not specified, both export and import sessions are displayed.

=item B<-s> I<session>

Filter by a specific session number.  Only sessions matching this number
will be displayed.  Useful for tracking a particular session across
multiple spans.

=item B<-e> I<engineId>

Filter by span engine ID.  Only the span with the specified remote engine
ID will be displayed.  If not specified, all configured spans are shown.

=item B<-h>

Display usage information and exit.

=back

=head1 ARGUMENTS

=over 4

=item I<interval>

Refresh interval in seconds.  If set to 0 or omitted, B<ltpwatch> runs in
one-shot mode: it displays the current status and exits immediately.

If a positive interval is specified, B<ltpwatch> will refresh the display
every I<interval> seconds until interrupted (Ctrl+C) or the count is
reached.

=item I<count>

Number of iterations to perform.  Only meaningful when I<interval> is
greater than 0.

=over 4

=item *

If I<interval> is 0 (or omitted), I<count> defaults to 1 (one-shot mode).

=item *

If I<interval> is greater than 0 and I<count> is omitted, B<ltpwatch>
runs indefinitely until interrupted.

=item *

If both I<interval> and I<count> are specified, B<ltpwatch> performs
exactly I<count> iterations with I<interval> seconds between each.

=back

=back

=head1 OUTPUT

B<ltpwatch> displays session information in a tabular format:

    === LTP Session Watch [2024-12-03 14:23:45] ===

    --- Span 2 ---

    EXPORT SESSIONS (Active: 3, Dead: 1)
      Session    Status             Client TotalLen   RedLen     Rexmit
      -------    ------             ------ ---------  ---------  ------
      10001      transmitting       1      65536      32768      0
      10002      buffering          1      131072     65536      0
      10004      completed          1      16384      16384      0

    IMPORT SESSIONS (Active: 2, Dead: 1)
      Session    Status             Client RedLen     Received   Rexmit
      -------    ------             ------ ---------  ---------  ------
      20001      receiving          1      65536      45000      0
      20003      completed          1      16384      16384      0

When B<-c> (summary count mode) is used, individual session rows are
replaced by a per-status count table:

    === LTP Session Watch [2024-12-03 14:23:45] ===

    --- Span 2 ---

    EXPORT SESSIONS (Active: 15, Dead: 4)
      buffering                3
      transmitting             8
      canceled(rexmit)         4

    IMPORT SESSIONS (Active: 10, Dead: 2)
      receiving                7
      complete-pending         3
      completed                2

When B<-a> (active-only) is combined with B<-c>, the header omits the
dead count and only active sessions are tallied:

    EXPORT SESSIONS (Active: 15)
      buffering                3
      transmitting             8

Note that the export and import tables have different column layouts.
In particular, the last three data columns differ between the two tables
(see L</"Column Descriptions"> below).

=head2 Export Session Columns

=over 4

=item B<Session>

The LTP session number, assigned by the sending engine.

=item B<Status>

Current session state (see L</"Export Session Status Values"> below).

=item B<Client>

Client service ID that owns this session (e.g., 1 for Bundle Protocol).

=item B<TotalLen>

Total block size in bytes, including both red (reliable) and green
(unreliable) portions.

=item B<RedLen>

Size of the red (reliable) portion of the block in bytes.  Only the red
portion is subject to LTP's retransmission-based reliability mechanism.

=item B<Rexmit>

Number of times this session's B<cancel segment> (CS) has been
retransmitted while awaiting a cancel-acknowledgment (CAS) from the
receiver.  This counter is always 0 for active sessions that have not been
canceled.  For canceled sessions (status C<canceled(...)>), it shows how
many times the cancel segment itself had to be retransmitted.

B<Important:> This is I<not> the checkpoint retransmission count.
Checkpoint retransmissions are tracked per individual checkpoint segment
and are not displayed by B<ltpwatch>.

=back

=head2 Import Session Columns

=over 4

=item B<Session>

The LTP session number, as assigned by the sending engine.

=item B<Status>

Current session state (see L</"Import Session Status Values"> below).

=item B<Client>

Client service ID that owns this session (e.g., 1 for Bundle Protocol).

=item B<RedLen>

Expected size of the red (reliable) portion of the block in bytes,
as declared by the sender.  This value is 0 until the receiver has
received enough information (typically the End-of-Red-Part or
End-of-Block marker) to determine the red part length.

=item B<Received>

Number of red-part bytes received so far.  When B<Received> equals
B<RedLen>, all reliable data has arrived (though the session may still
be waiting for report acknowledgments to complete).

=item B<Rexmit>

Number of times this session's B<cancel segment> (CR) has been
retransmitted while awaiting a cancel-acknowledgment (CAR) from the
sender.  This counter is always 0 for active sessions that have not been
canceled.  For canceled sessions (status C<canceled(...)>), it shows how
many times the cancel segment itself had to be retransmitted.

B<Important:> This is I<not> the report segment retransmission count.
Report retransmissions are tracked per individual report segment and
are not displayed by B<ltpwatch>.

=back

=head2 Export Session Status Values

=over 4

=item B<buffering>

Session is aggregating data into a block; the End-of-Block data segment
has not been sent yet.

=item B<transmitting>

End-of-Block has been sent but the final report acknowledgment has not
been received.  The session may be waiting for reports, retransmitting
checkpoints, or retransmitting data segments in response to negative
reports.

=item B<awaiting-cleanup>

Final acknowledgment received; session is being cleaned up.

=item B<green-only>

Session contains only green (unreliable, best-effort) data with no
red part, so no LTP reliability mechanisms apply.

=item B<completed>

Session completed successfully (in dead exports list, awaiting final
cleanup).

=item B<canceled(user)>

Session was canceled by explicit user request (via B<ltpcancel>).

=item B<canceled(unreachable)>

Session was canceled because the destination client service was
unreachable.

=item B<canceled(rexmit)>

Session was canceled because a retransmission limit was exceeded.
On the sender (export) side, this occurs when:

=over 4

=item *

A B<checkpoint> retransmission timer expired C<maxTimeouts> times without
receiving a report segment from the receiver.  C<maxTimeouts> is computed
from the link's segment loss rate (derived from C<maxBER> in legacy mode
or set explicitly via span configuration).

=item *

The total number of checkpoints sent for this session reached
C<maxCheckpoints>, a per-session limit computed from the block size
and expected segment loss rate.

=back

=item B<canceled(miscolor)>

Session was canceled due to a segment color mismatch (a green segment
was received for a session that had already received red segments, or
vice versa, in a way that violates LTP protocol rules).

=item B<canceled(engine)>

Session was canceled by the LTP engine for an internal reason not
covered by the other cancellation codes.

=back

=head2 Import Session Status Values

=over 4

=item B<receiving>

Session is actively receiving data segments from the sender.

=item B<complete-pending>

All red-part data has been received (B<Received> E<ge> B<RedLen>) and the
End-of-Block marker has arrived, but the final report/acknowledgment
exchange has not yet completed.

=item B<awaiting-delivery>

Final report has been acknowledged by the sender; the complete block
is awaiting delivery to the local client application.

=item B<delivered>

Data has been delivered to the client application (e.g., Bundle Protocol
agent).

=item B<completed>

Session completed successfully (in dead imports list, awaiting final
cleanup).

=item B<canceled(user)>

Session was canceled by explicit user request (via B<ltpcancel>).

=item B<canceled(unreachable)>

Session was canceled because the local client service was unreachable.

=item B<canceled(rexmit)>

Session was canceled because a retransmission limit was exceeded.
On the receiver (import) side, this occurs when:

=over 4

=item *

A B<report segment> retransmission timer expired C<maxTimeouts> times
without receiving a report-acknowledgment from the sender.
C<maxTimeouts> is computed from the link's segment loss rate (derived
from C<maxBER> in legacy mode or set explicitly via span configuration).

=item *

The total number of report segments sent for this session reached
C<maxReports>, a per-session limit computed from the block size and
expected segment loss rate.

=back

Note: a session may show B<Received> equal to B<RedLen> (all data
received) yet still be C<canceled(rexmit)>.  This happens when the
receiver received all data and sent a final report, but the sender
never acknowledged that report.  After the report retransmission limit
is exhausted, the receiver cancels the session even though all data
arrived.

=item B<canceled(miscolor)>

Session was canceled due to a segment color mismatch.

=item B<canceled(engine)>

Session was canceled by the LTP engine for an internal reason.

=back

=head1 EXIT STATUS

=over 4

=item "0"

B<ltpwatch> completed successfully.

=item "1"

B<ltpwatch> was unable to attach to LTP or encountered an error.

=back

=head1 EXAMPLES

=over 4

=item B<ltpwatch>

One-shot display of all sessions on all spans.

=item B<ltpwatch 5>

Refresh display every 5 seconds until interrupted.

=item B<ltpwatch 2 10>

Refresh every 2 seconds, for 10 iterations total.

=item B<ltpwatch -t export>

Show only export sessions (one-shot).

=item B<ltpwatch -t import -e 3>

Show only import sessions for span with engine ID 3.

=item B<ltpwatch -s 12345>

Find and display session 12345 across all spans.

=item B<ltpwatch -e 2 -t export 3>

Show export sessions for engine 2, refreshing every 3 seconds.

=item B<ltpwatch -a>

Show only active sessions (omit dead/completed/canceled), one-shot.

=item B<ltpwatch -c>

Summary count mode: show counts by status instead of individual sessions.

=item B<ltpwatch -a -c -t import>

Active import sessions only, summarized by status count.

=back

=head1 DIAGNOSTICS

The following diagnostics may be issued:

=over 4

=item ltpwatch can't attach to LTP.

B<ltpadmin> has not yet initialized LTP protocol operations.

=item LTP is not initialized.

The LTP database has not been created.  Run B<ltpadmin> first.

=item No spans configured.

No LTP spans have been added via B<ltpadmin>.

=item No span found for engine ID I<N>

The specified engine ID does not match any configured span.

=back

=head1 NOTES

=over 4

=item *

Recently completed or canceled sessions are only visible for a short
time while they remain in the "dead" session lists awaiting final
cleanup.  After cleanup, they will no longer appear in B<ltpwatch>
output.

=item *

LTP uses several distinct retransmission mechanisms that should not be
confused:

B<Checkpoint retransmission> (sender side): When the sender transmits a
checkpoint data segment and does not receive a report segment within the
expected round-trip time, it retransmits the checkpoint.  Each checkpoint
segment has its own retransmission timer and expiration count.  These
per-checkpoint counts are I<not> shown by B<ltpwatch>.

B<Report segment retransmission> (receiver side): When the receiver sends
a report segment and does not receive a report-acknowledgment from the
sender, it retransmits the report.  Each report segment has its own
retransmission timer and expiration count.  These per-report counts are
I<not> shown by B<ltpwatch>.

B<Cancel segment retransmission> (either side): After a session is
canceled, the canceling engine sends a cancel segment and waits for a
cancel-acknowledgment.  If the acknowledgment does not arrive, the cancel
segment is retransmitted.  The B<Rexmit> column in B<ltpwatch> shows
this cancel-segment retransmission count.

=item *

The C<maxTimeouts> parameter that governs checkpoint and report
retransmission limits is not directly configurable.  In legacy mode
(no explicit span loss-rate configuration), it is computed from the
link's bit error rate (C<maxBER>, default 0.000001) and the maximum
segment size, with a minimum of 3.  The computed value is logged at
span startup as:

    [i] Span to engine N ... max timeouts M.

=back
